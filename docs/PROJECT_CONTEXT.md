# Контекст проекта и границы текущей версии

Этот файл — единая точка отсчёта для разработчиков, тестировщиков и операторов проекта. Если формулировки в отдельных документах расходятся с ним, сначала уточняем реализацию, затем обновляем документацию.

Актуальность: 16 июля 2026 года.

## Продукт

«Гравитация» — закрытый клуб для директоров образовательных организаций Московской области. Основная ценность продукта — профессиональное общение, обмен опытом, мероприятия, поиск коллег и рабочие коммуникации внутри ограниченного сообщества.

В системе есть роли директоров, наставников и администраторов. Административные функции нужны для проверки заявок, управления контентом и поддержки сообщества; это не означает, что продукт открыт для массовой регистрации.

## Модель доступа

Операционная модель запуска — только по приглашениям. Целевой процесс: директор получает приглашение, подаёт заявку, после проверки получает доступ.

Текущая техническая реализация использует регистрацию-заявку и последующее одобрение администратором. Отдельная обязательная проверка invite-кода или одноразового токена в текущем коде не является реализованной функцией. Если приглашения должны технически блокировать любую регистрацию без токена, это отдельная задача разработки.

## Масштаб

1500 — ориентир верхней границы зарегистрированных аккаунтов, а не число одновременных пользователей. Фактическая аудитория закрытого клуба ожидается меньше. Перед постоянным запуском нужно подтвердить поведение приложения на выбранной инфраструктуре и отдельно выполнить нагрузочную проверку.

## Среды

- Локальная среда: разработка и ручная проверка; для тестов допускается pg-mem.
- Render: временный тестовый стенд. Он не считается постоянной production-инфраструктурой проекта.
- Постоянная среда: будет выбрана и настроена отдельно; для неё нужны PostgreSQL, резервное копирование, HTTPS, постоянное хранилище загрузок и согласованная стратегия масштабирования.

## Демо-режим

В проекте намеренно предусмотрены четыре демонстрационных директора. На экране входа показывается демонстрационная учётная запись `elena@school11.ru / demo1234` — это часть сценария демо и тестового стенда.

Демо-данные создаются только при включённом `DEMO_MODE=true` или `SEED_DEMO=true`. В постоянной среде эти параметры должны быть явно выключены, если демо-режим не входит в план запуска.

## Что уже реализовано

- регистрация и одобрение пользователей;
- профили, школы, фотографии и поиск директоров;
- наставники, события и регистрация на события;
- календарь, сообщения, уведомления и realtime-обновления;
- рейтинг, административная панель и служебные API;
- опциональные интеграции с Redis, SMTP, MAX, Web Push и OpenAI.

Приложение построено как единый Node.js/Express-сервер со SPA-фронтендом, API и WebSocket-каналом. Vite собирает фронтенд; service worker используется для push-уведомлений и обработки переходов, а не как полноценный offline-кэш.

## Операционные ограничения текущей версии

- загрузки пока хранятся в `public/uploads`; для постоянной среды требуется внешнее или иное постоянное объектное хранилище;
- Redis опционален для одного экземпляра, но необходим для общего rate limit и realtime-состояния при работе нескольких экземпляров;
- `REDIS_ENABLED=false` предназначен для локальных сценариев без Redis, а не как настройка постоянного многосерверного запуска;
- нагрузочные smoke-тесты не заменяют резервное копирование, мониторинг и проверку восстановления.
